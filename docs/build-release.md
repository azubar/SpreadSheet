# Збірка та Реліз компоненти SpreadSheet

Цей документ описує процес локальної збірки, тестування та автоматичного випуску релізів компоненти.

## Локальна збірка

Для збірки компоненти потрібне встановлене середовище Rust (stable, edition 2021).

### Крос-компіляція та цільові платформи

Компонента підтримує збірку під наступні цільові платформи:

```sh
# Windows x64 (64-бітний клієнт або сервер 1С)
cargo build -p spreadsheet --release --target x86_64-pc-windows-msvc
# Результат: target/x86_64-pc-windows-msvc/release/spreadsheet.dll

# Windows x86 (32-бітний клієнт 1С)
cargo build -p spreadsheet --release --target i686-pc-windows-msvc
# Результат: target/i686-pc-windows-msvc/release/spreadsheet.dll

# Linux x64 (64-бітний клієнт або сервер 1С)
cargo build -p spreadsheet --release --target x86_64-unknown-linux-gnu
# Результат: target/x86_64-unknown-linux-gnu/release/libspreadsheet.so
```

## Тестування

Для запуску стандартного набору unit-тестів та інтеграційних тестів виконайте:

```sh
cargo test -p spreadsheet
```

### Тестування на реальних файлах
Інтеграційні тести, що використовують реальні MXL-файли, очікують наявність каталогу `mxl-files/` або `Данные/` у проекті. Якщо цей каталог відсутній, відповідні тести на реальних файлах будуть автоматично пропущені.

Для масового рендерингу великої кількості тестових файлів з метою візуальної перевірки ви можете скористатися прикладом `render_all`:

```sh
cargo run -p spreadsheet --release --example render_all -- target/render 100
```

## Автоматичний Реліз на GitHub

Процес випуску нового релізу автоматизований за допомогою GitHub Actions:

1. **Створення тегу**: Створення та пуш Git-тегу вигляду `v*` (наприклад, `v0.6.3`) запускає CI/CD конвеєр.
2. **Збірка бінарників**: GitHub Actions автоматично компілює версії для всіх підтримуваних платформ (Windows x64, Windows x32, Linux x64).
3. **Пакування**: Всі зібрані бібліотеки разом із файлом `MANIFEST.XML` пакуються в єдиний архів `SpreadSheet.zip`, готовий для завантаження в макет конфігурації 1С/BAS як загальна зовнішня компонента.
4. **Публікація**: Створюється новий реліз на сторінці GitHub Releases, куди прикріплюються бінарні активи, архів ZIP та файл контрольних сум `SHA256SUMS.txt`.
