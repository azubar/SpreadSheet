# План доработок SpreadSheet и что для них нужно от вас

Документ описывает, что сделано в 0.7.1, что осталось и в каком порядке, и
пошагово — что нужно сделать на вашей стороне (в 1С), чтобы доработки,
зависящие от поведения платформы, можно было сделать точно.

---

## 1. Сделано в 0.7.1 (без вашего участия)

| Что | Зачем |
|---|---|
| Версия Rust закреплена (`rust-toolchain.toml`, 1.99.1) и в CI | Новые правила clippy больше не роняют CI внезапно |
| 32-битная DLL: предел картинки 60 Мпикс, входного MXL 40 МБ | В 32-битном процессе 1С буфер на 250 Мпикс не выделить — было бы аварийное завершение |
| Крупные буферы выделяются с проверкой (`try_reserve`) | Нехватка памяти — понятная ошибка, а не падение процесса 1С |
| Исправлена ширина страницы MXL при дополнительных группах колонок | Содержимое широких групп обрезалось на странице |
| JPEG-кодер `jpeg-encoder` | Кодирование JPEG в 2–3 раза быстрее при том же качестве и размере |
| Уровни сжатия PNG подобраны замером | «Обычно» вдвое быстрее при том же размере; «Быстро» — файл в 2–4 раза меньше |
| Тесты по эталонным картинкам (`spreadsheet/tests/golden.rs`) | Любое изменение рендера видно в тестах |
| Генератор вариантов MXL без 1С (`mxl-demo-collection/tools/mxl_variants.py`) | Регрессионные образцы печатных параметров |
| CI: сборка и clippy для x86 (32 бит), PDF-тесты на Linux с poppler | Раньше 32-битная сборка проверялась только при релизе, PDF на Linux не тестировался |
| Скрипты 1С для образцов и эталонов (`mxl-demo-collection/1c/`) | Для этапов ниже |

## 2. Сделано в 0.7.2 и 0.7.3 (бывшие этапы 0.8.0 и 0.9.0)

Сделано по документации 1С и разобранным образцам, **без сверки с 1С** —
сверка по эталонам из шага 3.1 остаётся обязательной.

| Версия | Что | Насколько точно |
|---|---|---|
| 0.7.2 | Режим «как при печати» (`РежимПечати`, `РазрешениеПечати`): лист нужного формата и ориентации, поля, масштаб печати, автомасштаб, ч/б печать | Формат, ориентация, поля, масштаб — из параметров документа; число страниц совпало с ручным расчётом на всех образцах; точное совпадение с `КоличествоСтраниц()` 1С не проверено |
| 0.7.2 | `СохранитьСтраницы`, `ОттенкиСерого`, DPI в файлах PNG/JPEG | Проверено тестами |
| 0.7.3 | Значения ячеек (число, дата, булево) и форматные строки 1С | Форма хранения `{"N"\|"D"\|"B", …}` — по стандартной сериализации 1С, в образцах её нет; правила `Формат()` — по документации |
| 0.7.3 | Выравнивание «по ширине», произвольный угол текста | Общий алгоритм; вид 1С не сверялся |

### Осталось — только с эталонами из 1С (шаг 3.1)

Формат хранения этих элементов в MXL не разобран: в имеющихся образцах их нет.

1. Колонтитулы (текст, номера страниц `[&НомерСтраницы]`) в режиме печати.
2. Повтор строк/колонок при печати (`ПовторятьПриПечатиСтроки`).
3. Отступ и автоотступ текста.
4. Скрытые строки и свёрнутые группировки.
5. Сверка: деление на страницы (с `КоличествоСтраниц()` и PDF 1С),
   представление значений (с `ОбразецЗначенияИФорматы`), повороты и
   выравнивание по ширине.

Скрипт `mxl-demo-collection/1c/СозданиеОбразцов.bsl` создаёт образцы ровно
для этих пунктов.

### Без вашего участия (параллельно)

- Рефакторинг `converter.rs` на модули `layout`, `text`, `draw`, `pages`,
  `print`, `encode`; разбиение `build_layout` и `draw_texts`.
- Типизированные ошибки вместо строк.
- Фаззинг парсера MXL (`cargo-fuzz`).

## 3. Что сделать на вашей стороне

### 3.1. Образцы и эталоны из 1С — главное

Нужен любой компьютер с 1С:Предприятие 8.3 (подойдёт пустая файловая база).

1. Скопируйте на этот компьютер:
   - `mxl-demo-collection/1c/СозданиеОбразцов.bsl`
   - `mxl-demo-collection/1c/ПодготовкаЭталонов.bsl`
   - каталог `mxl-demo-collection/generated/` (варианты, созданные без 1С).
2. Создайте внешнюю обработку (или общий модуль) и вставьте в модуль код
   обоих файлов `.bsl`.
3. Выполните (пути — свои):
   ```bsl
   СоздатьОбразцыSpreadSheet("C:\SpreadSheet\образцы");
   ```
   В каталоге появятся `ОбразецЗначенияИФорматы.mxl`,
   `ОбразецВозможностиТекста.mxl` и восемь файлов `ОбразецПечать_*.mxl`.
4. Скопируйте в `C:\SpreadSheet\образцы` ещё:
   - файлы из `mxl-demo-collection/generated/` — проверим, что 1С их
     открывает и как печатает;
   - **3–5 реальных печатных форм** из вашей конфигурации (счёт, ТОРГ-12 или
     УПД, акт, платёжное поручение…), сохранённых в MXL:
     `ТабличныйДокумент.Записать("…\Счет.mxl", ТипФайлаТабличногоДокумента.MXL)`.
     Если в них есть персональные данные — замените их на тестовые.
5. Выполните:
   ```bsl
   ПодготовитьЭталоныSpreadSheet("C:\SpreadSheet\образцы", "C:\SpreadSheet\эталоны");
   ```
   Для каждого MXL появятся `.pdf` (как печатает 1С) и `.json` (число
   страниц, формат, поля, масштаб и т.д.).
6. Передайте мне оба каталога: заархивируйте и приложите в чат или
   закоммитьте в ветку в `mxl-demo-collection/reference/`.

Если при выполнении скрипта возникнет ошибка (скрипты подготовлены без
доступа к 1С и не запускались) — пришлите текст ошибки и строку; поправлю.
Строку с недоступным в вашей версии свойством можно закомментировать.

### 3.2. Сведения о среде

Ответьте, пожалуйста:
- версия платформы 1С (например, 8.3.24.1586) и конфигурация (BAS, УТ, БП…);
- где работает компонента: на клиенте (тонкий/толстый, x86 или x64,
  Windows/Linux), на сервере (Windows/Linux), или и там и там;
- что важнее в режиме печати: точное совпадение страниц с 1С или просто
  «листы правильного формата»;
- какое разрешение картинок страниц нужно (96, 150, 200, 300 DPI).

### 3.3. Ручная проверка буфера обмена (5 минут)

Автотесты буфер обмена не проверяют (в CI нет дисплея). На клиенте 1С:
```bsl
Компонента.ПолучитьКартинкуВБуферОбмена("C:\…\накладная.mxl", "PNG");
```
затем вставьте (Ctrl+V) в Paint/Word (Windows) или в редактор картинок
(Linux). Особенно важен Linux-клиент: картинка должна вставляться и после
выполнения метода. Сообщите результат для каждой ОС.

### 3.4. Релиз

1. Посмотрите и примите PR (CI зелёный — сборка x64/x86/Linux и тесты).
2. После слияния поставьте тег: `git tag v0.7.3 && git push origin v0.7.3` —
   workflow `Release` соберёт DLL/SO и опубликует релиз с `SpreadSheet.zip`.
3. Проверьте в 1С 32- и 64-битную DLL на своих документах (подключение,
   `СохранитьКартинку`, `ПолучитьКартинку`, PDF).
