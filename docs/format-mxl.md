# Формат файлів MXL (табличний документ 1С 8.х)

Цей документ описує формат файлів `*.mxl` — табличних документів платформ 1С:Підприємство 8.2/8.3 та BAS (внутрішня назва формату — MXL8). Саме цей формат розбирає парсер компоненти (`spreadsheet/src/mxl_parser.rs`).

Формат офіційно не документований; наведений опис відновлено аналізом реальних файлів версій 8.1.9 та 8.1.12 і перевірено програмно. Розділи, що лишилися нерозшифрованими, позначено окремо — парсер обробляє їх терпимо (пропускає, не «падаючи»).

---

## 1. Загальна будова файлу

```
Зміщення  Розмір  Вміст
0         7       Сигнатура "MOXCEL\0"
7         2       versionHigh, WORD little-endian — завжди 8
9         2       versionLow,  WORD little-endian — завжди 1
11        2       versionSub,  WORD little-endian — 9, 12 тощо
13        3       BOM UTF-8 (EF BB BF)
16        …       Текстове тіло в UTF-8
```

Усе тіло — один великий об'єкт `{...}` у нотації скобкової серіалізації значень 1С 8 (та сама нотація використовується платформою і в інших службових файлах).

> **Увага**: розширення `.mxl` мала й застаріла платформа 1С 7.7, але то зовсім інший, бінарний формат. Його ознака — після `MOXCEL` ідуть п'ять нульових байтів і **байт версії `6` або `7`**. Такі файли компонента не підтримує.

---

## 2. Лексична граматика тіла

| Токен | Синтаксис |
|---|---|
| Початок об'єкта | `{` |
| Кінець об'єкта | `}` |
| Розділювач полів | `,` (пробіли, таби, CR/LF навколо токенів ігноруються) |
| Число | десяткові цифри, опційно зі знаком `-` |
| Рядок | `"..."`; лапка всередині подвоюється: `""` → `"` |
| Ідентифікатор | «гола» послідовність (GUID, адреса сховища тощо) |

Об'єкт — це `{`, поля через кому (числа, рядки, вкладені об'єкти, ідентифікатори), `}`. Імен полів немає; скільки полів читати і як їх тлумачити — визначає схема конкретного місця документа.

---

## 3. Корінь документа

Перші поля кореневого об'єкта:

```
{ 8, 1, <versionSub>,        — версія (дублює двійковий заголовок)
  {…},                        — мова/локаль
  {…}, {…}, <число>,          — службові поля
  {0,0} × 6,                  — службові блоки
  <число>, <число>,           — службові числа
  БЛОК РЯДКІВ,                — див. §4; починається з поля з індексом 15
  ХВІСТ ДОКУМЕНТА             — див. §5
}
```

У всіх перевірених файлах (v8.1.9, v8.1.12) блок рядків починається з **16-го поля кореня (индекс 15)**. Парсер додатково вміє знаходити блок рядків пошуком за формою — на випадок інших версій преамбули.

---

## 4. Блок рядків і комірок

```
ЧислоРядків: Число
на кожен рядок:
    НомерРядка:    Число        — рядки розріджені, номери зростають
    ФорматРядка:   Число        — індекс у таблиці форматів (§7), 1-базний;
                                    0 = формату немає (висота — авто)
    ЧислоКомірок:  Число
    на кожну комірку:
        НомерКолонки:  Число
        Об'єкт-комірка: {Маркер, ІндексФормату, ...}
```

**Маркер комірки** — бітова маска, що визначає, які поля йдуть після індексу формату (у цьому порядку):

| Біт | Значення | Поле, що додається |
|---|---|---|
| 1 (2) | типізоване значення | `{"S", "текст"}` — рядкове значення |
| 2 (4) | посилання-розшифровка | `{"#", GUID-типу, "адреса"}` — посилання на об'єкт бази |
| 4 (16) | локалізований текст | контейнер локалізованого рядка (§4.1) |

Практичні комбінації: `0` (порожня комірка, лише формат), `2`, `16`, `20` (= 16+4: посилання + кешований відображуваний текст).

### 4.1 Локалізований рядок

```
{ КількістьМов,      Число (звичайно 1)
  ЄТекст,            Число: 1 — далі йде текст, 0 — тексту немає
  { КодМови, Текст } — пара рядків, наприклад {"uk","Разом"}
}
```

Текст може містити переведення рядка всередині лапок — це багаторядкова комірка.

## 5. Хвіст документа (після блоку рядків)

Порядок для v8.1.9/8.1.12:

1. **Група колонок за замовчуванням** (§6);
2. число рядків (дублює блок рядків);
3. число K додаткових груп колонок і K груп тієї ж форми — так кодуються ділянки листа з різними ширинами колонок;
4. число пар P і P пар `(номер_рядка, номер_додаткової_групи)` — які рядки використовують яку додаткову групу; решта рядків — групу за замовчуванням;
5. **графічні об'єкти** (якщо є): Число, Число N, далі N записів рисунків (§9.1);
6. серед подальших службових полів — **об'єднання комірок**: `{N, {ліво, верх, право, низ, прапор} × N}` (координати включні; значущі записи з прапором 0), іменовані області (включно з іменами рисунків: `ім'я → {2, номер_рисунка, 0}`), `КлючПараметровПечати` (рядок), параметри друку (§5.1) і **область друку** (§5.2);
7. **таблиця форматів**: Число N, далі N записів формату (§7);
8. **таблиця шрифтів**: Число M, далі M записів шрифту (§8) — завжди безпосередньо після таблиці форматів;
9. далі — таблиця числових форматів, **таблиця кольорів** (§9) і **таблиця картинок** (§9.2).

### 5.1 Параметри друку

Об'єкт `{{0, N, (Ключ, {"Тип", Значення}) × N}}`. Ключі, встановлені розбором демо-файлів `ДемонстрацияПечатиРазрывов_*`: `0` — РазмерСтраницы (`{"S","A4"}`), `1` — ОриентацияСтраницы (1 книжна, 2 альбомна), `2` — МасштабПечати (%), `6`–`9` — поля зверху/зліва/знизу/справа (у 1/100 мм), `10`, `11` — колонтитули, `12` — АвтоМасштаб, `13` — ЧерноБелаяПечать, `16`/`17` — ширина/висота сторінки (мм). Рендерером поки не використовуються.

### 5.2 Область друку

`{Тип, Ліво, Верх, Право, Низ, GUID}` (0-базні, включні). Тип `0` — область не задана (координати `-1`), `3` — прямокутник; від'ємна межа означає «без обмеження» (області виду «рядки»/«колонки»). Приклад: `ОбластьПечати = R1C1:R49C12` → `{3,0,0,11,48,00000000-…}`.

### 5.3 Розриви сторінок

Явний розрив (`ВывестиГоризонтальныйРазделительСтраниц()` / `ВывестиВертикальныйРазделительСтраниц()`) зберігається у **форматі** рядка або колонки як значення поля «іншого виміру» з бітом 4:
* **горизонтальний розрив після рядка** — у форматі рядка встановлено біт 7 (ширина) зі значенням `4`, напр. `{192, 100, 4}` (висота 100 + розрив);
* **вертикальний розрив після колонки** — у форматі колонки (група колонок, §6) встановлено біт 6 (висота) зі значенням `4`, напр. `{192, 4, 144}` (розрив + ширина 144).

---

## 6. Група колонок

```
{ ЧислоКолонок, 0, GUID, ЧислоПар, (НомерКолонки, ІндексФормату) × ЧислоПар }
```

`ІндексФормату` — 1-базне посилання в таблицю форматів; з запису формату для колонки значуща ширина (біт 7, §7). Колонка, якої немає у групі, має типову ширину (9 символів = 72 одиниці).

---

## 7. Запис формату

Запис — це об'єкт `{Прапори, далі по одному числу на кожен установлений біт у порядку зростання бітів}`:

| Біт | Поле | Значення |
|---|---|---|
| 0 | шрифт | індекс у таблиці шрифтів, 0-базний |
| 1 | рамка ліворуч | індекс у таблиці ліній (§7.1), 0-базний |
| 2 | рамка згори | так само |
| 3 | рамка праворуч | так само |
| 4 | рамка знизу | так само |
| 5 | колір рамок | індекс у таблиці кольорів (§9), 0-базний |
| 6 | висота рядка | в 1/288 дюйма; 0 = автопідбір |
| 7 | ширина колонки | в 1/8 ширини стандартного символу (105 twips) |
| 8 | горизонтальне вирівнювання | 0 ліво, 2 право, 4 за шириною, 6 центр |
| 9 | вертикальне вирівнювання | 0 верх, 8 низ, 24 центр |
| 10 | колір тексту | індекс у таблиці кольорів (§9), 0-базний |
| 11 | колір фону | індекс у таблиці кольорів (§9), 0-базний |
| 12 | тип узору заливки | 255 = без узора, 0 = сплошний (колір узору), 1–17 = штриховки |
| 13 | колір узору | індекс у таблиці кольорів (§9), 0-базний |
| 14 | «контроль» тексту | 0 авто, 1 обрізати, 2 забивати (Block), 3 переносити (Wrap) |
| 18 | орієнтація тексту | кут у десятих частках градуса: 900 = 90° (вертикально) |

### 7.1 Поведінка «контролю» тексту (біт 14)
* **`0` (Авто)**: Якщо сусідні комірки праворуч порожні, текст виходить за межі своєї комірки. Якщо зайняті — обрізається.
* **`1` (Обрезать)**: Текст обрізається строго по ширині комірки (або об'єднаної області).
* **`2` (Забивать / Block)**: Якщо текст коротший за ширину комірки, він циклічно повторюється горизонтально до повного заповнення комірки. Рендер починається зліва (`x0 + pad`) і автоматично обрізається на правому краї (`x1`).
* **`3` (Переносить / Wrap)**: Текст переноситься на нові рядки по словах. Кількість ліній розраховується з урахуванням доступної ширини.

### 7.2 Посилання та індекси
* **Посилання на формати — 1-базні** (індекс `i` у комірці/рядку означає `formats[i-1]`, а `0` — відсутність формату).
* **Індекси ліній, кольорів, шрифтів — 0-базні**.

---

## 8. Таблиця ліній

Іде у преамбулі. Форма: `{ N, (1, {запис-лінії}, 0) × N }`. Запис лінії: `{4, 0, {..}, Тип, Товщина, КолірТег, GUID, 0}`.
* **Тип**: `0` — авто/немає лінії, `1` — сплошна, `2` — точкова, `3` — подвійна, `4` — редкий пунктир, `5` — частий пунктир, `6` — великий пунктир.
* **Товщина**: `1`–`3`.
* Рамки об'єднаних комірок зчитуються з **верхньої-лівої комірки** та малюються на межах всього об'єднання.

---

## 9. Запис шрифту

**Вид 0** (повний запис): `{7, 0, Прапори, Висота, 0, 0, 0, Насиченість, Курсив, Підкреслення, Закреслення, Кодування, x, x, x, 34, "Ім'я", x, 100}`.
* Висота — в десятих частках пункту (80 = 8 pt, 140 = 14 pt).
* Насиченість: жирний шрифт визначається значенням `>= 600`.
* Курсив/Підкреслення/Закреслення — `0/1`.
* Ім'я — єдиний рядок запису; за ним рендерер обирає сімейство Liberation Sans / Serif / Mono.

**Види 1–3** (перевизначення за маскою прапорів): `{7, Вид, Маска, [{база}], значення...}`; біт 0 маски — ім'я (рядок), 1 — висота, 2 — насиченість, 3 — курсив, 4 — підкреслення, 5 — закреслення.

---

## 10. Таблиця кольорів
* **Вид 0**: абсолютний колір RGB, записаний як `COLORREF` у форматі `BGR` (`R | G<<8 | B<<16`).
* **Вид 3**: автоматичний/стильовий колір (від'ємна службова ссилка).

---

## 11. Факти та особливості розробки рендерера

1. **COM STA Deadlock**: 1С працює в Single-Threaded Apartment (STA). Виклики асинхронних методів WinRT API `Windows.Data.Pdf` (таких як `.join()`) призводять до взаємного блокування (deadlock), оскільки STA очікує завершення без роботи черги повідомлень. Вирішення: **винесення всіх WinRT-операцій у фоновий MTA-потік** (`std::thread::spawn` з ініціалізацією `COINIT_MULTITHREADED`).
2. **Альфа-канал та Буфер Обміну**: Skia/tiny-skia використовує премультипліковані кольори (premultiplied alpha: `r*a/255`), тоді як системний буфер обміну (через бібліотеку `arboard`) очікує чистий RGBA (straight alpha). Усі етапи рендера дають непрозорі пікселі (сторінки PDF накладаються на білий фон), а для альфи 255 обидва подання збігаються — буфер передається без перетворення та копіювання.
3. **Блокування файлів PDF**: Використання `InMemoryRandomAccessStream` для читання PDF у Windows WinRT дозволяє повністю уникнути блокування файлів на диску, даючи змогу видаляти або перезаписувати вихідний PDF відразу після конвертації.
4. **Різна ширина сторінок PDF**: При рендерингу багатосторінкових PDF-документів з різною шириною сторінок, рендерер центрує кожну сторінку відносно максимальної ширини та заливає порожні бічні області білим кольором.
5. **Масштабування PDF WinRT**: WinRT не підтримує передачу DPI напряму. Обмеження обходиться розрахунком піксельних габаритів сторінки за формулою: $px = size \times \frac{DPI_{final}}{96}$, які передаються в `DestinationWidth`/`DestinationHeight` опцій `PdfPageRenderOptions`.
