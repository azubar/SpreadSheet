# Специфікація компоненти SpreadSheet

## Ідентифікація

- Технологія: Native API (`AddInNative`).
- Ім'я класу компоненти: **SpreadSheet**.
- Ідентифікатор при підключенні: `AddIn.<Символьне_ім'я>.SpreadSheet`.
- Бібліотеки: `spreadsheet_x86_64.dll` (Windows x64),
  `spreadsheet_i386.dll` (Windows x86, 32-бітний клієнт),
  `libspreadsheet_x86_64.so` (Linux x64).

## Властивості

Версія компоненти (з `Cargo.toml`), наприклад `"0.7.3"`.

### Качество / Quality

| | |
|---|---|
| Тип | Число (ціле) |
| Доступ | читання і запис |
| Типове значення | 90 |

Якість стиснення JPEG. Використовується лише коли `ТипКартинки = "JPEG"`. Для PNG ігнорується.

### Масштаб / Scale

| | |
|---|---|
| Тип | Число (ціле) |
| Доступ | читання і запис |
| Типове значення | 100 |
| Допустимі значення | 1–1000 |

Масштаб рендеру у відсотках від початкового розміру документа.

Для PDF підсумкова роздільна здатність дорівнює `РазрешениеPDF × Масштаб / 100` і застосовується без обмежень (наприклад, `РазрешениеPDF = 300`, `Масштаб = 200` дає 600 DPI). Розмір результату контролюється лімітами зображення (див. «Обмеження та помилки»), які перевіряються ще до растеризації сторінок.

### НомерСтраницы / PageNumber

| | |
|---|---|
| Тип | Число (ціле) |
| Доступ | читання і запис |
| Типове значення | 0 |
| Допустимі значення | 0 (всі сторінки) або 1..N |

Номер сторінки для конвертації (з `1`); кількість сторінок повертає `КоличествоСтраниц`.

- **PDF**: `0` — всі сторінки склеюються вертикально (з інтервалом `ИнтервалСтраницPDF`).
- **MXL**: `0` — весь документ однією картинкою (як раніше). `N` — сторінка `N`: область друку документа (`ОбластьПечати`, а без неї — вся таблиця), поділена явними горизонтальними та вертикальними розривами сторінок. Порядок сторінок — «спочатку вниз, потім праворуч». Вміст на межі сторінки (об'єднані комірки, текст, що виходить за комірку) обрізається, як при друку. Пам'ять виділяється лише під картинку сторінки, тому окремі сторінки можна отримати навіть з документа, який цілком у картинку не вміщується.

### СжатиеPNG / PngCompression

| | |
|---|---|
| Тип | Число (ціле) |
| Доступ | читання і запис |
| Типове значення | 1 |
| Допустимі значення | 0 (швидко), 1 (звичайно), 2 (максимально) |

Ступінь стиснення PNG (для JPEG ігнорується):

| Значення | Рівень deflate | Швидкість і розмір (документ 3027×3138 px) |
|---|---|---|
| `0` — швидко | 1 | ~25 мс, файл ~1,4× більший |
| `1` — звичайно | 4 | ~75 мс, розмір як у стандартного рівня zlib |
| `2` — максимально | максимальний | ~290 мс, файл на 1–3% менший |

Для документів з текстом PNG зазвичай менший за JPEG (типово в 1,5–3 рази) і не розмиває літери; JPEG доречний для документів з фотографіями.

### РежимПечати / PrintMode

| | |
|---|---|
| Тип | Булево |
| Доступ | читання і запис |
| Типове значення | Ложь |

Режим «як при друку» для MXL (для PDF не впливає). Кожна сторінка виводиться картинкою аркуша паперу:

- **формат і орієнтація** — `РазмерСтраницы` та `ОриентацияСтраницы` документа (A3, A4, A5, A6, B4, B5, Letter, Legal, Executive, Tabloid, Ledger, Statement; невідомий формат — розмір із файлу або A4);
- **поля** — `ПолеСверху/Слева/Снизу/Справа` документа, вміст розміщується від лівого верхнього кута області друку;
- **масштаб** — `МасштабПечати` документа, а при `АвтоМасштаб = Истина` — вписування області друку по ширині аркуша (лише зменшення);
- **сторінки** — область друку, поділена явними розривами та за розміром області друку аркуша; порядок «спочатку вниз, потім праворуч»; рядок, вищий за аркуш, займає окрему сторінку й обрізається;
- **ч/б друк** — при `ЧерноБелаяПечать = Истина` аркуш виводиться у відтінках сірого.

`НомерСтраницы = 0` — усі аркуші, склеєні вертикально з інтервалом `ИнтервалСтраницPDF`; `N` — аркуш `N`. `КоличествоСтраниц` повертає кількість аркушів.

Не реалізовано (формат зберігання в MXL ще не розібрано — потрібні еталони з 1С, див. `docs/plan-dorabotok.md`): колонтитули, повтор рядків/колонок на кожній сторінці. Поділ на сторінки відтворює логіку 1С наближено: точний збіг із `КоличествоСтраниц()` 1С буде перевірено на еталонах.

Роздільна здатність аркуша в режимі друку: A4 при 150 DPI — 1240×1754 px, при 300 DPI — 2480×3508 px.

## Методи

### СохранитьКартинку / SavePicture

```
СохранитьКартинку(ПутьКФайлу: Строка, ПутьКартинки: Строка, ТипКартинки: Строка) → Булево
```

| Параметр | Тип | Опис |
|---|---|---|
| `ПутьКФайлу` | Строка | Повний шлях до файлу `*.mxl` або `*.pdf` |
| `ПутьКартинки` | Строка | Повний шлях файлу результату; каталог має існувати |
| `ТипКартинки` | Строка | `"JPEG"` (або `"JPG"`) чи `"PNG"`, регістр не важливий |

### ПолучитьКартинку / GetPicture

```
ПолучитьКартинку(ПутьКФайлу: Строка, ТипКартинки: Строка) → ДвоичныеДанные
```

Повертає зображення значенням `ДвоичныеДанные` без запису на диск.

### ПолучитьКартинкуВБуферОбмена / GetPictureToClipboard

```
ПолучитьКартинкуВБуферОбмена(ПутьКФайлу: Строка, ТипКартинки: Строка) → Булево
```

Копіює згенероване зображення в системний буфер обміну (працює лише в клієнтському інтерактивному сеансі). Підключення до буфера обміну тримається, доки існує об'єкт компоненти: у Linux (X11/Wayland) вміст буфера обміну віддає процес-власник, тож картинка лишається доступною для вставки й після виклику методу.

### СохранитьКартинкуИзДанных / SavePictureFromData

```
СохранитьКартинкуИзДанных(Данные: ДвоичныеДанные, ПутьКартинки: Строка, ТипКартинки: Строка) → Булево
```

### ПолучитьКартинкуИзДанных / GetPictureFromData

```
ПолучитьКартинкуИзДанных(Данные: ДвоичныеДанные, ТипКартинки: Строка) → ДвоичныеДанные
```

### ПолучитьКартинкуИзДанныхВБуферОбмена / GetPictureFromDataToClipboard

```
ПолучитьКартинкуИзДанныхВБуферОбмена(Данные: ДвоичныеДанные, ТипКартинки: Строка) → Булево
```

Аналоги методів вище, але документ передається значенням `ДвоичныеДанные` (вміст файлу `*.mxl` або `*.pdf`). Тип документа визначається за вмістом: сигнатура `%PDF-` у першому кілобайті — PDF, інакше — MXL. Зручно на сервері, коли документ уже в пам'яті (наприклад, `ТабличныйДокумент.Записать(Поток)` або вміст тимчасового сховища): тимчасовий файл не потрібен.

### КоличествоСтраниц / PageCount

```
КоличествоСтраниц(ПутьКФайлу: Строка) → Число
```

### КоличествоСтраницИзДанных / PageCountFromData

```
КоличествоСтраницИзДанных(Данные: ДвоичныеДанные) → Число
```

Кількість сторінок документа: для PDF — кількість сторінок файлу (на Linux — за `pdfinfo`), для MXL — кількість сторінок за областю друку та явними розривами (див. `НомерСтраницы`), а в режимі друку — кількість аркушів. При помилці без винятку (`ВызыватьИсключения = Ложь`) повертає `0`.

### СохранитьСтраницы / SavePages

```
СохранитьСтраницы(ПутьКФайлу: Строка, ШаблонИмени: Строка, ТипКартинки: Строка) → Число
```

### СохранитьСтраницыИзДанных / SavePagesFromData

```
СохранитьСтраницыИзДанных(Данные: ДвоичныеДанные, ШаблонИмени: Строка, ТипКартинки: Строка) → Число
```

Зберігає кожну сторінку в окремий файл за один виклик (документ розбирається один раз): PDF — кожну сторінку файлу, MXL — сторінки за областю друку та розривами, у режимі друку — кожен аркуш. `{N}` у шаблоні замінюється номером сторінки (`C:\out\накладная_{N}.png`); без `{N}` номер додається перед розширенням (`накладная.png` → `накладная_1.png`). `ПоляКартинки`, `ОттенкиСерого`, `Качество`, `СжатиеPNG` застосовуються до кожного файлу. *Повертає:* кількість збережених файлів (при помилці без винятку — `0`).

### Роздільна здатність у файлі картинки

Кожен файл PNG/JPEG містить роздільну здатність (PNG — `pHYs`, JPEG — JFIF), щоб картинка друкувалася й вставлялася в документи в натуральну величину: екранний режим — `96 × Масштаб / 100` DPI, режим друку — `РазрешениеПечати`, PDF — `РазрешениеPDF × Масштаб / 100`.

## Значення комірок і форматні рядки

Комірка може містити не текст, а **значення** (`СодержитЗначение = Истина`; у друкованих формах так зазвичай заповнюються параметри макета: суми, кількості, дати). Компонента виводить таке значення за форматним рядком комірки (властивість `Формат`), як функція `Формат()` 1С з російською локаллю:

| Тип | Параметри | Без форматного рядка |
|---|---|---|
| Число | `ЧЦ`, `ЧДЦ`, `ЧС`, `ЧРД`, `ЧРГ`, `ЧГ`, `ЧН`, `ЧВН`, `ЧО` (а також `ND`, `NFD`, `NS`, `NDS`, `NGS`, `NG`, `NZ`, `NLZ`, `NN`) | групи розрядів через нерозривний пробіл, дробова частина через кому, нуль — порожній рядок |
| Дата | `ДФ` (шаблон `d`, `dd`, `ddd`, `dddd`, `M`…`MMMM`, `yy`, `yyyy`, `H`, `HH`, `h`, `hh`, `m`, `mm`, `s`, `ss`, `tt`), `ДЛФ` (`D`, `DD`, `T`, `DT`, `DDT`), `ДП` | `дд.ММ.гггг Г:хх:сс`; порожня дата — порожній рядок |
| Булево | `БЛ`, `БИ` | «Да» / «Нет» |

Число округлюється в десятковому записі (без похибок двійкової арифметики), половина — від нуля. Назви місяців і днів тижня — російською (`MMMM` після числа дня — у родовому відмінку: «19 июля»).

Точність відтворення окремих випадків (ведучі нулі з групуванням, `ЧО`, `ЧС`) буде звірено з еталонами 1С (`mxl-demo-collection/1c/СозданиеОбразцов.bsl`, файл `ОбразецЗначенияИФорматы.mxl`).

## Вирівнювання і поворот тексту

- **По ширині** (`ГоризонтальноеПоложение.ПоШирине`): рядки перенесення, крім останнього в абзаці, розтягуються на ширину комірки за рахунок пробілів; останній рядок абзацу й одиночний рядок — ліворуч.
- **Орієнтація тексту**: довільний кут (`ОриентацияТекста`); блок рядків повертається проти годинникової стрілки й вирівнюється в комірці (за замовчуванням — по центру). Висота рядка з автопідбором враховує повернутий блок.

Не реалізовано (формат зберігання в MXL ще не розібрано — потрібні еталони з 1С): відступ і автовідступ тексту, приховані рядки, згорнуті групування.

## Шрифти

Назва шрифту комірки визначає вбудоване метрично сумісне сімейство:

| Шрифти документа | Шрифт рендеру |
|---|---|
| Arial, Tahoma, Verdana, Calibri та інші без зарубок | Liberation Sans |
| Times New Roman, Georgia, Cambria, Garamond та інші з зарубками | Liberation Serif |
| Courier New, Consolas, Lucida Console та інші моноширинні | Liberation Mono |

Символи, яких немає в Liberation (✓, стрілки, математичні та інші знаки), відображаються запасним шрифтом DejaVu Sans. Вбудовані картинки масштабуються з фільтрацією (без «драбинки» при зменшенні та «квадратиків» при збільшенні).

## Обмеження та помилки

У разі помилки метод генерує виняток платформи (повертає `Ложь` та відправляє опис через `AddError`), а текст помилки зберігається у властивості `ОписаниеОшибки`. Якщо `ВызыватьИсключения = Ложь`, виняток не генерується (див. вище). Тексти помилок — російською мовою.

Усі властивості перевіряються до читання файлу та рендеру: некоректне значення одразу дає помилку з назвою властивості.

- Максимальний розмір зображення — 65 500 px за кожною стороною та 250 мегапікселів за площею (у 32-бітній компоненті `spreadsheet_i386.dll` — 60 мегапікселів: адресний простір 32-бітного процесу 1С не вміщує більших буферів). Ліміти перевіряються до виділення пам'яті, а великі буфери виділяються з перевіркою, тому завеликий або пошкоджений документ дає помилку, а не аварійне завершення процесу 1С.
- Для PDF розмір підсумкового зображення перевіряється до растеризації сторінок (на Linux — за даними `pdfinfo`, на Windows — за розмірами сторінок WinRT).
- Запис у файл атомарний: зображення пишеться в тимчасовий файл поруч і перейменовується, тож при помилці не лишається обрізаного файлу, а попередній файл з тим самим ім'ям зберігається.
- Максимальний розмір вхідного файлу MXL — 200 МБ (у 32-бітній компоненті — 40 МБ).
- Окрема сторінка MXL вимагає, щоб сторінки були задані областю друку чи явними розривами: автоматичний поділ за розміром аркуша паперу не виконується.
- На Linux-сервері для роботи з PDF потрібні утиліти `pdftoppm` та `pdfinfo` (пакет `poppler-utils`). Час їх роботи обмежено 120 с — після цього процес зупиняється, а метод повертає помилку.
