# Специфікація компоненти SpreadSheet

## Ідентифікація

- Технологія: Native API (`AddInNative`).
- Ім'я класу компоненти: **SpreadSheet**.
- Ідентифікатор при підключенні: `AddIn.<Символьне_ім'я>.SpreadSheet`.
- Бібліотеки: `spreadsheet_x86_64.dll` (Windows x64),
  `spreadsheet_i386.dll` (Windows x86, 32-бітний клієнт),
  `libspreadsheet_x86_64.so` (Linux x64).

### Масштаб / Scale

| | |
|---|---|
| Тип | Число (ціле) |
| Доступ | читання і запис |
| Типове значення | 100 |
| Допустимі значення | 1–1000 |

Масштаб рендеру у відсотках від початкового розміру документа.

Для PDF підсумкова роздільна здатність дорівнює `РазрешениеPDF × Масштаб / 100` і застосовується без обмежень (наприклад, `РазрешениеPDF = 300`, `Масштаб = 200` дає 600 DPI). Розмір результату контролюється лімітами зображення (див. «Обмеження та помилки»), які перевіряються ще до растеризації сторінок.

| | |

| Тип | Булево |
| Доступ | читання і запис |
| Типове значення | Истина |

`Истина` — помилка методу генерує виняток платформи. `Ложь` — метод не генерує винятку, а повертає `Ложь` (`СохранитьКартинку`, `ПолучитьКартинкуВБуферОбмена`) або порожні `ДвоичныеДанные` (`ПолучитьКартинку`); текст помилки — у властивості `ОписаниеОшибки`.

## Методи

### СохранитьКартинку / SavePicture

```
СохранитьКартинку(ПутьКФайлу: Строка, ПутьКартинки: Строка, ТипКартинки: Строка) → Булево
```

| Параметр | Тип | Опис |
|---|---|---|
| `ПутьКФайлу` | Строка | Повний шлях до файлу `*.mxl` або `*.pdf` |
| `ПутьКартинки` | Строка | Повний шлях файлу результату; каталог має існувати |
| `ТипКартинки` | Строка | `"JPEG"` (або `"JPG"`) чи `"PNG"`, регістр не важливий |

### ПолучитьКартинку / GetPicture

```
ПолучитьКартинку(ПутьКФайлу: Строка, ТипКартинки: Строка) → ДвоичныеДанные
```

Повертає зображення значенням `ДвоичныеДанные` без запису на диск.

### ПолучитьКартинкуВБуферОбмена / GetPictureToClipboard

```
ПолучитьКартинкуВБуферОбмена(ПутьКФайлу: Строка, ТипКартинки: Строка) → Булево
```

Копіює згенероване зображення в системний буфер обміну (працює лише в клієнтському інтерактивному сеансі).

## Обмеження та помилки

У разі помилки метод генерує виняток платформи (повертає `Ложь` та відправляє опис через `AddError`), а текст помилки зберігається у властивості `ОписаниеОшибки`. Якщо `ВызыватьИсключения = Ложь`, виняток не генерується (див. вище). Тексти помилок — російською мовою.

Усі властивості перевіряються до читання файлу та рендеру: некоректне значення одразу дає помилку з назвою властивості.

- Максимальний розмір зображення — 65 500 px за кожною стороною та 250 мегапікселів за площею. Ліміти перевіряються до виділення пам'яті, тому завеликий або пошкоджений документ дає помилку, а не аварійне завершення процесу 1С.
- Для PDF розмір підсумкового зображення перевіряється до растеризації сторінок (на Linux — за даними `pdfinfo`, на Windows — за розмірами сторінок WinRT).
- Запис у файл атомарний: зображення пишеться в тимчасовий файл поруч і перейменовується, тож при помилці не лишається обрізаного файлу, а попередній файл з тим самим ім'ям зберігається.
- Максимальний розмір вхідного файлу MXL — 200 МБ.
- На Linux-сервері для роботи з PDF потрібні утиліти `pdftoppm` та `pdfinfo` (пакет `poppler-utils`). Час їх роботи обмежено 120 с — після цього процес зупиняється, а метод повертає помилку.
